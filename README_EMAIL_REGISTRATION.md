# 복구 이메일 등록 추가 수정본

이전 ZIP에 빠져 있던 환경설정 → 사용자 관리의 복구 이메일 입력/수정/목록을 추가했습니다.
기준 소스는 첨부된 v12 계열이며 기존 아이디 로그인과 데이터를 유지합니다.

## 반드시 두 곳에 반영
1. Supabase의 기존 `admin-users` Edge Function을 이 ZIP의 `supabase/functions/admin-users/index.ts` 전체 코드로 교체하여 배포합니다. 기존 함수의 환경 변수 및 설정은 유지합니다. CLI를 사용한다면 해당 프로젝트에 연결한 뒤 `supabase functions deploy admin-users`로 배포할 수 있습니다.
2. ZIP 내용을 GitHub 저장소 루트에 반영합니다. 특히 settings.html, js/users.js를 교체하세요. 첫 복구 버전을 적용하지 않았다면 전체 파일을 반영하세요. 기존 운영 js/config.js 값은 유지합니다.
3. GitHub Pages 배포 후 Ctrl+F5로 새로고침합니다.
4. 관리자 로그인 → 환경설정 → 사용자 관리 → 사용자 목록에서 수정 → 복구 이메일 입력 → 사용자 저장.
5. 목록에 이메일이 표시되는지 확인하고 로그아웃 후 비밀번호 찾기에서 그 이메일로 요청합니다. 새 비밀번호 설정 후 기존 아이디로 로그인합니다.

GitHub에 함수 소스 파일을 올리는 것만으로 Supabase 함수가 배포되지는 않습니다.
이전 서버가 남아 있으면 안내 문구가 표시되고 사용자 저장이 차단됩니다.

## 저장 규칙
- 신규 계정은 실제 복구 이메일이 필수입니다.
- 기존 계정의 이메일을 비워 저장하면 기존 주소를 유지합니다. 비우기는 이메일 삭제가 아닙니다.
- 내부 @daekyung.local 주소는 목록에서 미등록으로 표시합니다.
- 관리자가 본인 소유임을 확인한 주소를 등록하며, 서버가 확인된 주소로 저장합니다. 별도의 이메일 소유권 확인 메일은 발송하지 않습니다. 주소를 정확히 확인하세요.
- 이메일은 profiles에 별도 복제하지 않고 Supabase Auth에 저장합니다. 사용자 ID는 유지됩니다. 별도 SQL 변경은 필요하지 않습니다.
- 다른 계정에 이미 등록된 이메일이면 저장 오류가 표시됩니다.
- 이메일 저장 후 다른 프로필 정보 저장만 실패하는 경우 이를 별도로 안내합니다.
- 기존 GITHUB_SUPABASE_SETUP.md의 Dashboard에서 직접 이메일을 수정하라는 안내 대신 이번 사용자 관리 기능을 사용할 수 있습니다.

모의 서버 검증: 관리자 권한, 이메일 형식, 생성/변경/조회, 기존 ID 유지, 빈값 보존, 중복 오류 및 부분 저장 오류 처리 통과.
기존 복구 테스트도 통과했습니다. 운영 서버 배포와 실제 이메일 발송은 수행하지 않았습니다.

공식 API: https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid
